# 如何补充和更新资料

## 上传一个文件

1. 在 GitHub 打开 `site/files/`，进入对应类别、型号和版本目录。
2. 点击 **Add file → Upload files**，上传用于对客提供的文件。新文件名建议使用英文、数字和短横线，保持分享链接简洁稳定。
3. 提交改动并合并至 `main`。下载中心会自动发现文件、计算大小与校验值，并生成下载入口。
4. 如需清晰的中英德标题、产品、语言与版本，在 `data/library.json` 的 `files` 对象中为该文件路径增加资料信息，可参照现有记录。没有填写时，下载中心使用文件名。
5. 在 Actions 中等待 **Validate and publish download library** 成功，再检查客户链接。页面更新日期会取资料文件／目录信息的最近提交日期与登记日期中的较晚者；它不代表原厂文档的修订日期。

每个类别中的 README 用于管理说明，不会变成客户下载条目。PDF、ZIP、常见模型和办公格式可直接收录；网站资料入口用 `resources` 登记。

## 版本和链接

- 在型号下建立明确的版本目录，例如 `site/files/01-manuals/steinadler-pro-l7e/2026-09-source/`。
- 型号、配置、语言和文件中可见版本应准确登记。没有文档版本号时，不把下载日期当成制造商发布版本。
- 已分享文件保持原路径；新版本使用新路径，同时更新目录标题或说明。不要悄悄用不兼容版本覆盖旧链接。
- 公开资料的来源 URL、下载日期和原文件 SHA-256 可保存在 `data/provenance.json`。

## 大文件

大于 50 MiB 的视频或模型包使用 GitHub Releases。上传资源后，把其永久下载 URL、实际字节数和 SHA-256 登记到 `data/library.json` 的 `resources`，`kind` 设置为 `file`。参考现有电池视频与字幕资料包。

资料包不可只含 Git LFS 指针或需要额外账号授权的链接。每个大型资料包都应实际测试匿名下载。

## 资料边界

这是公开仓库，文件及提交历史可被访问。只上传已决定对客提供的材料。内部邮件、聊天、报价、合同、客户个人资料和保密研发文件继续保存在内部主库。

## 本地检查

```sh
python3 scripts/build_catalog.py
python3 scripts/validate_catalog.py
python3 -m http.server 8000 --directory site
```

检查桌面及手机布局、中英德切换、文件预览、下载和复制链接，再合并发布。


## 公开范围与重复资料

- 公开库收录产品手册、认证与检测资料、售后及配件说明、产品参数和对客展示素材。
- 内部研发、工程评审、项目会议纪要、投标及客户保密方案不进入公开 Git 历史、Pages 或 Releases；同系列附件和混合压缩包也须检查。
- 已签保密协议、采购合同和客户专属交易材料保留在内部资料中。
- 历史资料保留原文版本、日期及适用范围，不自动标记为最新有效版本。
- 已被图文指南完整覆盖的视频和字幕不再另设重复资料包；电池更换统一使用现有图文指南入口。
- 来源对照表保存在本地。公开目录不得包含本机路径、私人 Drive 或邮箱链接。
